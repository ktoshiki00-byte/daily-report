# LINE 日報ボット

食器メーカー国内営業スタッフ向けの LINE 日報システムです。
平日18:00に届くお知らせから、1画面のフォームで午前・午後をまとめて入力できます。

> 📖 **日々の使い方・スタッフの追加/削除の手順は [MANUAL.md](MANUAL.md) を参照してください。**
> このREADMEは初回セットアップ（構築）の手順書です。

---

## 機能概要

| 機能 | 内容 |
|------|------|
| 自動お知らせ | 平日 18:00 に全員へ送信（ボタンから入力フォームを開く） |
| 入力フォーム | LIFFで1画面。午前・午後の行動種別・訪問先・内容・メモをまとめて入力 |
| 行動種別 | 商談 / 移動・外出 / メーカー訪問 / 展示会 / 社内作業 / 工場対応 |
| 自動保存 | Google スプレッドシートに午前1行・午後1行で保存 |
| 日報の照会 | 「確認」から1日分・月別・期間指定で照会 |
| 週次まとめ | 「週次まとめ」で自分の今週分。金曜19:30に自動送信 |
| 入力状況まとめ | 平日19:30に管理者へ入力済みの人と内容・19:30時点で未入力の人を送信 |
| 休暇・有給 | 休暇申請 → 管理者が[承認][却下] → 本人に通知・有給の残日数を減算 |

## セットアップ手順

### ① LINE Developers の設定

1. [LINE Developers コンソール](https://developers.line.biz/) にアクセスしログイン
2. **新規プロバイダー** を作成（または既存を選択）
3. **Messaging API チャネル** を新規作成
4. チャネル設定ページで以下を取得・メモ：
   - **チャネルシークレット**（Basic settings タブ）
   - **チャネルアクセストークン（長期）**（Messaging API タブ → Issue ボタンをクリック）
5. Messaging API タブで **Webhookの利用** を **オン** にする
   （Webhook URL は後ほど Render のデプロイ後に設定）
6. **応答メッセージ** と **あいさつメッセージ** を **オフ** にする（自動返信と競合するため）

---

### ② Google Cloud / スプレッドシートの設定

#### 2-1. Google Cloud プロジェクトを作成

1. [Google Cloud コンソール](https://console.cloud.google.com/) にアクセス
2. 画面上部の **プロジェクトを選択** → **新しいプロジェクト** を作成

#### 2-2. API を有効化

1. 左メニュー → **APIとサービス** → **ライブラリ**
2. 「Google Sheets API」を検索して **有効にする**
3. 「Google Drive API」を検索して **有効にする**

#### 2-3. サービスアカウントを作成

1. 左メニュー → **IAMと管理** → **サービスアカウント**
2. **サービスアカウントを作成** をクリック
3. 名前を入力（例: `daily-report-bot`）して作成
4. 作成したサービスアカウントをクリック → **キー** タブ → **キーを追加** → **新しいキーを作成**
5. 形式 **JSON** を選択 → ダウンロードされる `.json` ファイルを保存

#### 2-4. スプレッドシートを作成・共有

1. [Google スプレッドシート](https://sheets.google.com/) で新規スプレッドシートを作成
2. スプレッドシートの **URL** からシート ID をコピー
   例: `https://docs.google.com/spreadsheets/d/【ここがシートID】/edit`
3. スプレッドシートの **共有** ボタンを押し、サービスアカウントのメールアドレス
   （例: `daily-report-bot@your-project.iam.gserviceaccount.com`）を **編集者** として追加

> シートは初回起動時に自動作成されます。「日報」シートと「users」シートが作られます。

---

### ③ Render.com へのデプロイ

#### 3-1. GitHubにコードをプッシュ

```bash
git init
git add .
git commit -m "initial commit"
git remote add origin https://github.com/あなたのユーザー名/リポジトリ名.git
git push -u origin main
```

#### 3-2. Render でウェブサービスを作成

1. [Render.com](https://render.com/) にログイン（GitHub アカウントで登録推奨）
2. ダッシュボードで **New +** → **Web Service** をクリック
3. **Connect a repository** でさきほどのGitHubリポジトリを選択
4. 以下を設定：

| 項目 | 値 |
|------|----|
| Name | 任意（例: `daily-report-bot`） |
| Region | Singapore（日本に近い） |
| Branch | main |
| Runtime | Python 3 |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn app:app` |
| Instance Type | **Free** |

5. **Create Web Service** をクリック

#### 3-3. 環境変数を設定

デプロイ完了後、Render ダッシュボードのサービスページ → **Environment** タブで以下を追加：

| Key | Value |
|-----|-------|
| `LINE_CHANNEL_SECRET` | LINE チャネルシークレット |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE チャネルアクセストークン |
| `GOOGLE_CREDENTIALS` | サービスアカウントJSONファイルの**中身全体**をそのまま貼り付け |
| `GOOGLE_SHEET_ID` | スプレッドシートのID |
| `LIFF_ID` | 日報入力フォームのLIFF ID（⑥で取得） |
| `LINE_LOGIN_CHANNEL_ID` | LINEログインチャネルのチャネルID（⑥で取得） |

> `GOOGLE_CREDENTIALS` の貼り付け方：ダウンロードした JSON ファイルをテキストエディタで開き、`{` から `}` までの全文字列をコピーして貼り付けてください。

> `LIFF_ID` と `LINE_LOGIN_CHANNEL_ID` は両方揃って初めて入力フォームが有効になります。
> 未設定の場合、フォームは「未設定です」と表示し、送信APIは 503 を返します。

設定後 **Save Changes** → サービスが自動的に再デプロイされます。

#### 3-4. デプロイURLの確認

Render ダッシュボードのサービス名の下に表示される URL（例: `https://daily-report-bot.onrender.com`）をメモしておきます。

### ④ LINE Webhook URL の設定

1. LINE Developers コンソール → 作成したチャネル → **Messaging API** タブ
2. **Webhook URL** に以下を入力：
   `https://あなたのRenderURL/webhook`
   例: `https://daily-report-bot.onrender.com/webhook`
3. **検証** ボタンを押して「Success」が表示されればOK
4. **Webhookの利用** が **オン** になっていることを確認

### ⑤ cron-job.org の設定

定期送信は外部サービス「cron-job.org」から各エンドポイントを叩いて行います
（Render無料プランは15分でスリープするため、アプリ内スケジューラーは使いません）。

1. [cron-job.org](https://cron-job.org/) にアクセスしてアカウント登録（無料）
2. **アカウント設定でタイムゾーンを `Asia/Tokyo` にする** ← 先にこれをやる
3. ダッシュボードで **CREATE CRONJOB** をクリックして以下を登録

| Title | URL | Schedule（JST） |
|-------|-----|----------------|
| 日報入力のお知らせ | `https://あなたのRenderURL/reminder` | 平日 18:00 |
| 提出状況まとめ（管理者） | `https://あなたのRenderURL/report` | 平日 19:30 |

> ⚠️ **UTC と JST**: サーバー（Render）はUTCで動きますが、アプリ側の時刻判定は
> JSTに変換済みです。cron-job.org のタイムゾーンを `Asia/Tokyo` にしておけば、
> 上の表の時刻がそのまま日本時間として動作します。

金曜の週次まとめ（管理者に全員分、各スタッフに自分の分）は `/report` の中から
続けて送られるため、**専用のジョブは不要**です。

### ⑥ LIFF（日報入力フォーム）の設定

日報の入力はLIFFフォームで行います。LIFFは**LINEログインチャネル**に登録します
（Messaging APIチャネルには作れません）。

1. LINE Developers コンソールを開く
2. **Botと同じプロバイダー**を選ぶ
   > ⚠️ **最重要**: ユーザーIDはプロバイダー単位で発行されます。別のプロバイダーに
   > 作るとLIFFで取得したユーザーIDがBot側と一致せず、誰の日報か特定できません。
3. **新規チャネル作成** → **LINEログイン** を選ぶ（名前は例: `日報フォーム`）
4. 作成したチャネルの **LIFF** タブ → **追加**

| 項目 | 値 |
|------|----|
| LIFFアプリ名 | 日報入力 |
| サイズ | Full |
| エンドポイントURL | `https://あなたのRenderURL/liff/report` |
| スコープ | `openid` と `profile` の両方にチェック |
| 友だち追加オプション | On (normal) |

> `openid` がないとIDトークンが発行されず、本人を特定できません。

5. 発行された **LIFF ID**（例: `1234567890-AbcdEfgh`）をメモ
6. **チャネル基本設定** タブの **チャネルID**（数字）をメモ
   > LIFF IDの `-` より前の数字とは別物です。
7. Render の **Environment** に `LIFF_ID` と `LINE_LOGIN_CHANNEL_ID` を追加（3-3参照）

### ⑦ リッチメニューの設定（任意）

コードでは設定していません。LINE Official Account Manager から手動で設定します。

1. [LINE Official Account Manager](https://manager.line.biz/) を開く
2. 対象のアカウント → **ホーム** → **リッチメニュー** → **作成**
3. 表示設定（タイトル・表示期間）を入力
4. **コンテンツ設定** でテンプレートを選び、背景画像を設定
   > 背景画像は必須です。テンプレートは作成画面の「デザインガイド」から
   > ダウンロードできます（推奨サイズ 2500×1686px）
5. 各エリアのアクションを設定

| エリア | アクション | 設定値 |
|--------|-----------|--------|
| 日報を入力 | リンク | `https://liff.line.me/あなたのLIFF_ID` |
| 週次まとめ | テキスト | `週次まとめ` |
| 日報を確認 | テキスト | `確認` |
| 使い方 | テキスト | `使い方` |

6. **保存**

> 「確認」は管理者・スタッフ共通で使えます。管理者は全員分を選んで照会でき、
> スタッフは自分の分だけが返ります。

## ユーザー登録方法（スタッフ向け）

1. LINE で日報ボットを**友だち追加**
2. **「登録する」** を押す（または **「登録」** と送信）
3. 「✅ ○○さんを登録しました！」と返信が来れば完了

登録後は平日18:00に日報入力のお知らせが届きます。

> **友だち追加しただけでは登録されません。** 「登録する」を押した時点で
> `users` シートに LINE表示名・ユーザーID・登録日 が記録されます。
> 管理者側の手作業は不要です。

退職者を通知対象から外すには `users` シートの**行を削除**します。
詳しくは [MANUAL.md](MANUAL.md) を参照してください。

## 日報入力フロー

```
平日18:00 お知らせが届く
    ↓
仕事が終わったら「日報を入力」を押す（または「日報入力」と送信）
  ※ 18:00に入力する必要はない。残業した日は終わった時間に入力する
    ↓
入力フォームが開く
  ※ 初回はプロフィールへのアクセス許可 → 「許可する」
    ↓
1画面で午前・午後をまとめて入力
  ・午前の行動種別を選ぶ（なし も選べる）
      商談 / メーカー訪問 / 展示会・イベント → 訪問先を入力
      移動・外出                            → 移動先を入力
      社内作業 / 工場対応                    → 内容のみ
  ・午後も同様に選ぶ
  ・自由メモ（任意・午前と午後の両方に記録される）
    ↓
「送信する」
    ↓
✅ 記録しました → 自動で閉じる
```

- 午前・午後の**両方を「なし」にすると送信できません**（どちらかは入力が必要）
- 保存に失敗した場合はフォームにエラーが表示され、入力内容を残したまま再送信できます
- 日報シートには従来どおり**午前1行・午後1行**で記録されます

### 締切ルール

- 日報は **当日24:00（JST）まで** 受け付けます
- 日付は**送信した瞬間のJSTの日付**で記録されます。24:00を過ぎた入力は
  自動的に翌日の日報になります（フォームに日付欄はなく、遡り入力はできません）
- 締切を過ぎても**シートへの自動書き込みは行いません**。未入力者は未入力のままです
- 19:30のまとめは締切前の集計のため、未入力者は「19:30時点で未入力」として表示し、
  「入力は本日24時までです。」を添えています（この時点では未提出は確定しません）

|----|------|

| 列 | 内容 |
|----|------|
| A | LINE表示名 |
| B | ユーザーID |

## よくあるトラブル

| 症状 | 確認ポイント |
|------|------------|
| Webhookの検証が失敗する | `LINE_CHANNEL_SECRET` の値が正しいか確認 |
| メッセージが届かない | `LINE_CHANNEL_ACCESS_TOKEN` が正しいか確認。Render のログを確認 |
| スプレッドシートに保存されない | サービスアカウントのメールがスプレッドシートの「編集者」に追加されているか確認 |
| お知らせが届かない | cron-job.org の URL・時刻・タイムゾーン（`Asia/Tokyo`）を再確認 |
| Render が起動しない | `GOOGLE_CREDENTIALS` に JSON が正しく貼れているか確認（改行・クォートに注意） |
| フォームが「未設定です」と表示される | `LIFF_ID` と `LINE_LOGIN_CHANNEL_ID` の**両方**が Render に設定されているか確認 |
| フォーム送信で「ログイン情報を確認できませんでした」 | `LINE_LOGIN_CHANNEL_ID` が LIFF の属する LINEログインチャネルのチャネルIDか確認 |
| フォームは開くが誰の日報か特定できない | LINEログインチャネルが Bot と**同じプロバイダー**にあるか確認 |
| フォームでIDトークンが取得できない | LIFFのスコープに `openid` が入っているか確認 |

## 注意事項

- **Render 無料プラン**: 15 分間アクセスがないとサーバーがスリープします。cron-job.org のリクエストで自動的に起動しますが、最初の応答に 30〜60 秒かかることがあります。
- **インメモリ状態管理**: 休暇申請の入力待ち状態はサーバーメモリで管理しています。サーバー再起動時に入力途中の状態はリセットされます（通常運用では問題ありません）。日報はフォームから一括送信するため影響を受けません。
- **プロバイダーを揃える**: LINEログインチャネルは必ず Bot と同じプロバイダーに作成してください。プロバイダーが異なるとユーザーIDが別の値になり、日報を本人と紐づけられません。
